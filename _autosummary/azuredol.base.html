azuredol.base#

Close-to-metal Mapping stores over Azure Blob Storage.

Three concrete classes:

  • ContainerStore — the primary store. Mapping of blob name → bytes within one container.

  • AccountStore — mapping of container name → ContainerStore within one account.

  • BlobHandle — non-Mapping escape hatch for one blob with the full Azure surface.

See misc/docs/architecture.md Layer B. Codec / convenience layers live in azuredol.recipes; the connection layer lives in azuredol.connection.

__setitem__ creates a container; the value is ignored except when it’s a Mapping (in which case it is treated as an initial bulk-load).

__delitem__ refuses non-empty containers — call azuredol.ops.delete_container(store, name, force=True) to acknowledge a cascading delete. See misc/docs/design_decisions.md §12.

Thin facade over one BlobClient. Not a Mapping.

Use when you need the full Azure-blob surface for a single blob: metadata, properties, conditional writes, leases, copy, append, SAS URL generation, streaming downloads.

Parameters:

  • container (Union[str, ContainerClient]) – An existing ContainerClient or a container name string.

  • blob (str) – The blob name (relative to the container root; full path including ‘/’).

  • connection (Union[AzureConnection, BlobServiceClient, str, dict, None]) – Ignored if container is a ContainerClient. Otherwise resolved via AzureConnection.from_anything.

Iteration / membership / cardinality (__len__ deliberately omitted) over a container.

__len__ is intentionally NOT implemented — see misc/docs/design_decisions.md §2. Pagination cost is unbounded; users wanting a count call sum(1 for _ in store).

walk_ids(delimiter='/')[source]#

Hierarchical walk of the leaf’s prefix, yielding BlobProperties / BlobPrefix nodes.

Thin pass-through to ContainerClient.walk_blobs. The scope is the leaf’s own prefix and each node’s .name is an absolute blob id (never a store key), so under a dol key codec it disagrees with __iter__. For a scope that follows the caller’s (possibly wrapped) store use azuredol.ops.walk(store).

Return type:

Iterator[Any]

class azuredol.base.ContainerStore(container, *, prefix='', connection=None, create_container_if_missing=False, blob_type=BlobType.BLOCKBLOB, upload_kwargs=None, download_kwargs=None)[source]#

Bases: ContainerReader, KvPersister

The primary read-write Mapping over an Azure container.

Doctest below requires Azurite (or live Azure). It is shown but not auto-run.

Example (requires Azurite):

>>> from azuredol import ContainerStore
>>> s = ContainerStore(
...     'my-test-container',
...     connection='UseDevelopmentStorage=true',
...     create_container_if_missing=True,
... )
>>> s['k1'] = b'v1'
>>> s['k1']
b'v1'
>>> 'k1' in s
True
>>> del s['k1']

For unit tests without Azurite, prototype with dol’s in-memory pattern: wrap_kvs(dict(), ...).
