azuredol#

Access Azure Blob Storage through a Mapping interface.

azuredol exposes Azure Blob Storage as dol-style Mapping / MutableMapping interfaces.

Quick start:

from azuredol import azure_store

# Uses connection_string env var or Azurite (UseDevelopmentStorage=true)
store = azure_store(
    'mycontainer',
    connection_string='UseDevelopmentStorage=true',
    create_container_if_missing=True,
)

store['k1'] = b'hello world'
store['k1']               # → b'hello world'
'k1' in store             # → True
del store['k1']

See misc/docs/architecture.md for the layered design.

Holds a resolved credential and a lazy BlobServiceClient.

This is the dependency-injection seam for the whole package. Tests construct one pointing at Azurite without touching any store class.

Parameters:

  • account_url (Optional[str]) – storage account URL (with or without credential).

All four args are optional; the credential cascade in resolve_credential is consulted if none are provided.

Hierarchical walk of the leaf’s prefix, yielding BlobProperties / BlobPrefix nodes.

Thin pass-through to ContainerClient.walk_blobs. The scope is the leaf’s own prefix and each node’s .name is an absolute blob id (never a store key), so under a dol key codec it disagrees with __iter__. For a scope that follows the caller’s (possibly wrapped) store use azuredol.ops.walk(store).

azuredol.substore(store, key)[source]#

The sub-store of store under key (a key ending in '/'), as the caller sees it.

substore(store, 'a/')[k] is store['a/' + k] for every wrapper stack on store (up to the key limits below). On a bare ContainerStore it is the cheap, server-scoped store['a/'] (listing only a/’s blobs). On anything wrapped (a dol key/value codec or scope, including the classes typed_store/AzureJsonStore build) it is a KeyCodecs.prefixed(key) view of that store, so the caller’s key and value mappings still apply; that view lists the wrapped store’s whole scope and keeps the keys under key. (store['a/'] on a store wrapped as an instance is minted by the innermost class and does not know about the wrappers: i2mint/azuredol#6.)

The cheap path needs a leaf that does not override _id_of_key (a subclass that maps keys

gets the view). Attribute lookups on the view fall through to the wrapped store, so .prefix and .walk_ids() of a view describe the parent’s scope: use walk() on it. Needs dol>=0.3.75 (its prefix view skips out-of-scope keys when iterating).

Parameters:

  • store – a ContainerReader/ContainerStore, wrapped or not

  • key (str) – a key ending in '/', without a leading '/' or an inner '//'

azuredol.typed_store(decode, encode, *, base=<class 'azuredol.base.ContainerStore'>)[source]#

A base (default ContainerStore) class with values decode(bytes) / encode(obj) -> bytes.

Unlike a bare wrap_kvs(ContainerStore, obj_of_data=..., data_of_obj=...), the trailing-slash sub-store convention keeps working: store['2026/'] comes back as a sub-store of the same typed class, instead of being fed to decode (i2mint/azuredol#4).

azuredol.walk_container(store, delimiter='/')#

Hierarchical walk (BlobProperties / BlobPrefix nodes) of store’s own scope.

The scope is the blob prefix the caller’s empty key resolves to, so a key codec’s prefix is included (a codec that is not a pure prefix, e.g. a suffix, raises ValueError; unlike ContainerCollection.walk_ids, which sees only the leaf’s prefix).

Return type:

Iterator[Any]
